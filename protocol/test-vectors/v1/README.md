# Protocol v1 test vectors

These files are the SHARED FIXTURE for protocol version 1.0.0
(`protocol/v1.0.0.md`): the ML pipeline implementation and `verify.py`
MUST both pass every vector in this directory, byte-for-byte and
value-for-value, before either is considered conformant. A disagreement
with a vector is a bug in the implementation, not in the vector.

The vectors were generated by executing the algorithms of the protocol
in Python (hashlib/hmac/json only), never hand-computed. The worked
examples embedded in `protocol/v1.0.0.md` (§3.1, §5.3) come from the
same execution and MUST agree with these files.

- `canonical.json` — canonical serialization (§3): three cases, including
  a non-ASCII string (BMP escape + astral surrogate pair) and
  shortest-round-trip floats. `canonical` is the exact byte string;
  `sha256` is SHA-256 over those bytes.
- `hkdf.json` — HKDF-SHA256 (§4.2): the RFC 5869 Appendix A.1 reference
  vector, plus the leaf salt for leaf_id `chronos/QQQ` and the
  archive_key derived from the fixed 32-byte week_seed
  `00112233445566778899aabbccddeeff00112233445566778899aabbccddeeff`
  with empty salt and L = 32.
- `merkle.json` — Merkle tree (§5): five commitments (SHA-256 of the
  ASCII strings `tsw:example:0` … `tsw:example:4`), expected roots for
  the 1-, 2-, 3-, and 5-leaf trees over those commitments in order,
  the 3-leaf intermediates, and one inclusion proof (index 2 of the
  5-leaf tree). Proof siblings are node hashes, not commitments.
- `indices.json` — audit index derivation (§9.3): a synthetic
  beacon_signature of 64 bytes of 0xab, week `2026-W35`, leaf_count
  357, with the expected K (= 20) and the first K indices in
  acceptance order.

These files are fixtures, pretty-printed for readability; they are not
canonical-serialization artifacts and their own bytes are not hashed by
the protocol.
